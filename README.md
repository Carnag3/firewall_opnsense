# OPNsense & Synology NAS: Диагностика деградации линка и настройка Destination NAT

Практический кейс по устранению деградации скорости канала провайдера и оптимизации удалённого резервного копирования на Synology NAS после миграции офисной сети на маршрутизатор **OPNsense 26.7.9_1**.

## Стек и архитектура
* **Маршрутизатор:** OPNsense 26.7.9_1 (FreeBSD)
* **WAN-подключение:** Физический интерфейс `WAN_LINK` (`re1`) + логический L2TP-туннель `WAN` (`l2tp0`, MTU 1400)
* **LAN-сегмент:** `192.168.0.0/24` (`1000baseT <full-duplex>`)
* **Хранилище:** Synology NAS (`192.168.0.20`), доступ через QuickConnect / Drive / Hyper Backup

---

## Проблема 1: Падение скорости канала и зависание удалённых подключений

### Симптомы
* Удалённые пользователи испытывали сильные задержки при работе с базами 1С, тогда как внутри локальной сети (`LAN`) всё работало без задержек.
* На дашборде OPNsense в блоке **Gateways** шлюзы `WAN_L2TP` и `BEELINE_LINK_DHCP` сигнализировали о росте задержек (RTT) и потерь пакетов, а исходящий трафик упирался в потолок ~8 Мбит/с.

### Диагностика и решение
1. Анализ журнала файрвола (**Firewall → Log Files → Live View**) показал, что рабочие сессии проходят со статусом `pass`, а блокируются только внешние сканеры портов (`Default deny`).
2. Проверка статуса физических интерфейсов (**Lobby → Dashboard → Interfaces**) выявила, что порт провайдера согласовался в аварийном режиме **`10baseT/UTP <full-duplex>`** (10 Мбит/с) вместо гигабита/100 Мбит/с.
3. Причина — нарушение контакта на одножильном кабеле Cat5e UTP при монтаже. После переобжима коннекторов RJ-45 по стандарту **T568B** линк поднялся до **`100baseTX`**, а потери пакетов на шлюзах прекратились.

## Проблема 2: Скорость резервного копирования на Synology NAS упала до 15 КБ/с

### Симптомы
* После замены старого роутера на OPNsense скорость входящих бэкапов на Synology NAS (`192.168.0.20`) упала до ~15 КБ/с.

### Причина
* В OPNsense по умолчанию закрыты входящие порты и отключён UPnP. Из-за отсутствия прямого доступа служба **Synology QuickConnect** автоматически переключила трафик на резервную ретрансляцию через облачный **Synology Relay Server**, который ограничивает пропускную способность.

### Решение: Настройка Destination NAT в OPNsense
Для возврата прямого соединения без посредников в разделе **Firewall → NAT → Destination NAT** настроены правила проброса TCP-портов с `WAN address` на внутренний IP NAS (`192.168.0.20`) с автоматической генерацией правил фильтрации (`Add associated filter rule`):

| Правило | Интерфейс | Протокол | Внешний порт | Целевой IP | Целевой порт | Назначение |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `Synology_Drive_6690` | WAN (IPv4) | TCP | `6690` | `192.168.0.20` | `6690` | Synology Drive Server |
| `Synology_DSM_5000` | WAN (IPv4) | TCP | `5000` | `192.168.0.20` | `5000` | DSM / WebDAV (HTTP) |
| `Synology_DSM_5001` | WAN (IPv4) | TCP | `5001` | `192.168.0.20` | `5001` | DSM / WebDAV (HTTPS) |
| `Synology_Backup_6281` | WAN (IPv4) | TCP | `6281` | `192.168.0.20` | `6281` | Hyper Backup |

## Результат
* Физический канал провайдера стабильно работает на `100 Мбит/с` без потерь пакетов на шлюзе.
* Входящие подключения к NAS фиксируются в **Firewall → Log Files → Live View** со статусом `pass`.
* Synology QuickConnect переключился с Relay-сервера на прямой канал, скорость резервного копирования восстановлена.
